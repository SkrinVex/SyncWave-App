# 🔐 Руководство по CI/CD, подписи APK и автоматическим релизам через GitHub Actions

В репозитории настроен автоматический воркер GitHub Actions (`.github/workflows/android-build.yml`), который компилирует Android-приложение, подписывает его вашим релизным ключом и публикует готовый `.apk` в **GitHub Releases**.

---

## 📋 Шаг 1. Конвертация ключа подписи (.jks / .keystore) в Base64

Для того чтобы GitHub Actions мог безопасно использовать ваш ключ без добавления бинарного файла в репозиторий, ключ шифруется в строку **Base64**.

### Если у вас Linux или macOS:
Выполните команду в терминале (замените `my-release-key.jks` на путь к вашему файлу):

```bash
base64 -w 0 my-release-key.jks > keystore_base64.txt
```
> **Результат**: Создастся текстовый файл `keystore_base64.txt` с одной длинной строкой.

---

### Если у вас Windows (PowerShell):
Откройте PowerShell и выполните:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("my-release-key.jks")) | Out-File -Encoding ASCII keystore_base64.txt
```

---

### Если у вас еще нет своего ключа (создание нового ключа):
```bash
keytool -genkey -v -keystore syncwave-release.jks -alias syncwave -keyalg RSA -keysize 2048 -validity 10000
```
*(Запомните введенные пароли и алиас!)*

---

## 🔑 Шаг 2. Добавление секретов в GitHub

1. Откройте ваш репозиторий на GitHub в браузере.
2. Перейдите в **Settings** (Настройки репозитория) → слева вкладка **Secrets and variables** → **Actions**.
3. Нажмите зеленую кнопку **New repository secret** и добавьте следующие **4 секрета**:

| Название секрета | Значение | Описание |
| :--- | :--- | :--- |
| `KEYSTORE_BASE64` | *Содержимое файла `keystore_base64.txt`* | Ваш ключ, закодированный в одну длинную строку base64 |
| `KEYSTORE_PASSWORD` | `ваш_пароль_от_хранилища` | Пароль от файла хранилища ключей (Store Password) |
| `KEY_ALIAS` | `syncwave` | Имя алиаса ключа (Key Alias) |
| `KEY_PASSWORD` | `ваш_пароль_ключа` | Пароль самого ключа (Key Password) |

> 💡 *Примечание:* Если секреты еще не добавлены, воркер автоматически соберет отладочный (`debug`) APK без ошибок, чтобы сборка не ломалась.

---

## 🏷️ Шаг 3. Запуск автоматической сборки через Git Tag

Каждый раз, когда вы хотите выпустить новую версию приложения, достаточно создать и запушить Git-тег:

### 1. Убедитесь, что все изменения закоммичены:
```bash
git add .
git commit -m "Release version 1.0.0"
git push origin main
```

### 2. Создайте тег с версией (например, `v1.0.0`):
```bash
git tag v1.0.0
```

### 3. Отправьте тег на GitHub:
```bash
git push origin v1.0.0
```

---

## ⚡ Что произойдет после пуша тега:

1. **GitHub Actions** автоматически обнаружит тег `v1.0.0`.
2. Запустится воркер `Build & Release Android APK`.
3. Приложение соберется на JDK 17, подставит версию `versionName="1.0.0"` и подпишет APK вашим сертификатом.
4. В разделе **Releases** вашего репозитория появится новый релиз **«SyncWave App v1.0.0»** с прикрепленными готовыми файлами:
   - `syncwave-app-1.0.0.apk` (подписанный релизный APK)
   - `syncwave-app-latest.apk`

---

## 🔄 Дополнительно: Ручной запуск и обычные пуши

- **Обычный push в ветку `main`**: Воркер автоматически соберет APK для тестирования и сохранит его во вкладке **Actions** → конкретная сборка → **Artifacts** (хранится 30 дней).
- **Ручной запуск (Manual Trigger)**: Вкладка **Actions** → воркер `Build & Release Android APK` → кнопка **Run workflow** справа.

---

## 🗑️ Удаление тега (если ошиблись с номером версии):
```bash
# Удалить тег локально:
git tag -d v1.0.0

# Удалить тег на GitHub:
git push --delete origin v1.0.0
```
